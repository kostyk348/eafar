# Contributing — EAFAR

PR приветствуются. Правила короткие, но жёсткие — они о детерминизме.

## Незыблемое

1. **Ноль зависимостей.** Ни runtime-, ни dev-зависимостей. Бенчмарк — на `std::time::Instant`,
   PNG-экспорт — свой писатель, RNG — свой SplitMix64. Предложение зависимости — сначала issue.
2. **Детерминизм не обсуждается.** Обход активных регионов — по возрастанию id (`BTreeSet`/
   `BTreeMap`, никаких `HashMap` в поведенческих путях); порядок float-операций в ядрах
   диффузии фиксирован; `f32` не заменяется на `f64` молча.
3. **Снапшоты бит-точные.** Любое новое поле мира обязано сериализоваться через биты
   (`to_bits`/`from_bits`) — паттерны NaN и `-0.0` переживают откат.
4. **`cargo test` зелёный** перед каждым коммитом; `cargo build --all-targets` без предупреждений;
   `unsafe` запрещён на уровне крейта.

## Рабочий процесс

1. Ветвь от `main`: `git checkout -b feat/моя-фича`.
2. Тесты на новое поведение — рядом с кодом или в `tests/suite/` (по образцу контрактных).
3. PR → зелёный CI (build + test; cross-check по платформам — неблокирующий) → merge.
   Изменения фиксируются в `CHANGELOG.md`.

## Стиль коммитов

`feat: | fix: | test: | docs: | ci: | build: <что изменилось>` — на английском или русском:

```
feat: per-automaton periods with async clocks
fix: diffusion keeps energy across region borders
test: bit-exact rollback with NaN payloads
```

## Контрактные тесты

Каждый критерий спецификации — один тест (так перенесён набор C++). Новая функциональность
идёт в паре с тестами; изменения, затрагивающие детерминизм, обязаны добавить
реплей-тест (тот же сид → та же история) и, если затронуты поля мира, — тест отката.

## Лицензия

Внося вклад, вы соглашаетесь, что ваш код распространяется под Apache-2.0.
